## 2. Bugs

### BL-13 · ~~`chart_roulette` blocks the event loop with synchronous `spz.get_data()`~~ — FALSE POSITIVE

| Field | Value |
|---|---|
| **Severity** | ~~High~~ → n/a |
| **File** | `speasy_proxy/api/v1/chart_roulette.py:33` |
| **Category** | Concurrency / correctness |
| **Verdict** | **FALSE POSITIVE** |

**Why it was rejected.** `chart_roulette` is a plain `def` (not `async def`). FastAPI dispatches non-coroutine path operations through the threadpool — verified in the installed fastapi 0.136.3 (`routing.run_endpoint_function`: `if is_coroutine: await dependant.call(...) else: await run_in_threadpool(dependant.call, ...)`). The event loop is never blocked. BACKLOG BL-2 already refers to "the threadpooled `chart_roulette` endpoint", and the proposed fix would merely nest a threadpool call inside the existing one (behavioral no-op).

**Residual (minor, not the original claim):** a hanging provider can occupy a shared anyio worker thread for up to 3× the fetch timeout; under heavy `chart_roulette` traffic this pressures the common threadpool. Same property as every sync endpoint; Low severity at most.

**Resolution (2026-08-06):** none — false positive, no change made.

### BL-14 · `bokeh_backend.plot_data` mutates shared `SpeasyVariable` in place — LEGIT BUT OVERSTATED, superseded by BL-31

| Field | Value |
|---|---|
| **Severity** | Medium → Low |
| **File** | `speasy_proxy/backend/bokeh_backend.py:230` |
| **Category** | Correctness / side effect |
| **Verdict** | **Legit code observation; claimed impact unreachable; proposed fix incomplete — see BL-31** |

**Verified.** `data.replace_fillval_by_nan(inplace=True)` does mutate the passed-in object, and the `to_json` path (`get_data.py:54`) indeed uses the non-inplace form with `convert_to_float=True` — the inconsistency is real.

**However**, the "mutation leaks to the client" scenario is unreachable: the variable comes from speasy's diskcache, which deserializes a fresh object on every `get_data` call, and the object is never reused after encoding within a request. The fix is harmless hygiene, not a leak fix.

**Important:** the proposed fix (`data = data.replace_fillval_by_nan()`) is incomplete — without `convert_to_float=True` it still raises on integer data with `FILLVAL` (verified, see BL-31). Apply the BL-31 fix instead; it resolves both.

**Resolution (2026-08-06):** FIXED via the BL-31 change. Reproducer `test_plot_data_does_not_mutate_input_variable` (red→green).

### BL-15 · ~~Bokeh `max_interval` uses `timedelta64` instead of milliseconds~~ — FALSE POSITIVE

| Field | Value |
|---|---|
| **Severity** | ~~Medium~~ → n/a |
| **File** | `speasy_proxy/backend/bokeh_backend.py:181, 214` |
| **Category** | Correctness |
| **Verdict** | **FALSE POSITIVE** |

**Why it was rejected.** Verified empirically with the installed bokeh 3.9.1: its serializer converts timedelta values to milliseconds for datetime ranges.

```python
>>> DataRange1d(max_interval=np.timedelta64(7, 'D'))  # serialized attributes
{'max_interval': 604800000.0}   # exactly 7 days in ms
```

Both call sites (assignment at :181 and constructor kwarg at :214) go through the same property/serializer. There is no 10⁶ error and the zoom clamp engages as intended. The proposed "fix" (`7*24*3600*1000`) produces the identical serialized value — a no-op.

**Resolution (2026-08-06):** none — false positive, no change made.

### BL-31 · NEW · `plot_data` silently fails on integer data with `FILLVAL` (missing `convert_to_float=True`)

| Field | Value |
|---|---|
| **Severity** | Medium |
| **File** | `speasy_proxy/backend/bokeh_backend.py:230` |
| **Category** | Correctness (missed by original review) |
| **Verdict** | **New finding — real bug, verified** |

**Problem.** `plot_data` calls `data.replace_fillval_by_nan(inplace=True)` *without* `convert_to_float=True`. Verified against the installed speasy: for an integer-dtype variable with a `FILLVAL`, the NaN assignment raises `ValueError: cannot convert float NaN to integer` — both inplace **and** on a copy (so BL-14's proposed fix fails identically). The exception is swallowed by `plot_data`'s blanket `except` (:279), so `format=html_bokeh` returns "Oops, unable to plot …" for any integer product with fill values. The other two call sites do it right: `to_json` (`get_data.py:54`) and `chart_roulette` (`chart_roulette.py:38`) both pass `convert_to_float=True`.

**Fix approach** (also resolves BL-14):

```python
# Before
data.replace_fillval_by_nan(inplace=True)

# After
data = data.replace_fillval_by_nan(convert_to_float=True)
```

**Reproducer (per project workflow, red→green):** build an int32 `SpeasyVariable` with `FILLVAL` set, call `plot_data(..., format path html_bokeh)` → currently returns the "Oops" string; after the fix returns a rendered HTML page.

**Resolution (2026-08-06):** FIXED — `data = data.replace_fillval_by_nan(convert_to_float=True)` (non-inplace, float conversion, same as the json path). Reproducer `test_line_plot_with_integer_fillval_data_renders` (red→green).

### BL-32 · NEW · `chart_roulette` returns raw 500s on edge-case products

| Field | Value |
|---|---|
| **Severity** | Low |
| **File** | `speasy_proxy/api/v1/chart_roulette.py:15-39, 46` |
| **Category** | Robustness (missed by original review) |
| **Verdict** | **New finding** |

Several unhandled paths surface as HTTP 500 instead of the intended friendly fallback:
- `_parameter_range` is typed `Optional[DateTimeRange]` (speasy `DataProvider._parameter_range`); a `None`/dateless range makes line 25 raise `AttributeError`/`TypeError`.

- `random_pick_product` raises `IndexError`/`KeyError` if a hardcoded provider (`amda`/`cda`/`ssc`) has an empty or missing flat inventory (e.g. provider was down at inventory build).
- The `... or "Oops try again"` fallback at :46 is **dead code**: `plot_data` always returns a truthy string.

**Fix approach:** wrap the pick+fetch in try/except and return the "Oops, try again" HTML on any failure; optionally draw the provider list from the actually-built inventories.

**Resolution (2026-08-06):** FIXED — the endpoint wraps pick+fetch in try/except and serves the friendly fallback on any failure; the dead `or "Oops try again"` is gone. Reproducers `test_empty_inventory_returns_friendly_page`, `test_missing_parameter_range_returns_friendly_page`, `test_too_short_range_returns_friendly_page` (all red→green).

### BL-33 · NEW · `ws_collaboration` lazy init lets early connections grab an unstarted server

| Field | Value |
|---|---|
| **Severity** | Low (endpoint disabled by default) |
| **File** | `speasy_proxy/api/v1/ws_collaboration.py:21-27` |
| **Category** | Concurrency (missed by original review) |
| **Verdict** | **New finding (characterization corrected during implementation)** |

The global is assigned *before* `await started.wait()`, and there is no yield between the `None` check and the assignment — so two servers are never created, but a concurrent second connection returns the server **before its `start()` has completed** and would `serve()` on an unstarted server.

**Resolution (2026-08-06):** FIXED — double-checked locking with an `asyncio.Lock`: the server is published only after `started.wait()` completes, and waiters block until then.
